# M²Shelf 产品规格

本文描述当前稳定产品行为。实现细节见 `PROJECT_CONTEXT.md`，不可静默改变的工程选择见 `DECISIONS.md`。

## 1. 产品身份

- 用户品牌：**M²Shelf**
- 技术名称：**M2Shelf**
- 副标题：**MORI MEDIA SHELF**
- 平台：Windows x64
- 定位：本地优先、媒体源只读的媒体资源浏览与整理工具

M²Shelf 面向已经把动画、电影及相关资源保存在本地硬盘、移动硬盘或 NAS 映射目录中的用户。它在独立数据库中建立索引，让不同目录结构可被统一浏览，不要求用户先重命名或重排文件。

## 2. 核心原则：源文件只读

Library Root 及其后代是用户资产，应用只读取，不得：

- 新建、移动、重命名或删除媒体目录中的文件；
- 修改媒体内容、目录结构或时间戳；
- 写入 NFO、海报、字幕、数据库或临时文件；
- 把应用标签、收藏夹或绑定信息写回媒体目录。

下列信息只属于应用数据库或应用缓存：

- 扫描索引和人工显示名称；
- 人工分类与忽略状态；
- Bangumi 绑定和多语言标题；
- 封面缓存路径与错误状态；
- 用户标签、收藏夹和最近观看；
- 界面、播放器、缓存、窗口和排序设置。

删除资源库只删除 M²Shelf 的索引，不删除磁盘内容。

## 3. 资源库与扫描

### 3.1 Library Root

用户可以添加多个本地或 Windows 可访问的映射目录。每个 Root 有独立显示名称、路径和最近扫描时间；修改显示名称不改变真实目录名。

### 3.2 扫描行为

扫描必须：

- 递归读取任意深度目录；
- 支持 Unicode、空格和方括号路径；
- 每次进入目录或读取文件前确认规范化路径仍位于当前 Library Root 内，跳过链接和越界重解析路径；
- 按配置的视频扩展名索引视频；
- 单独索引字幕、图片、音频、文档、压缩包、字体、播放列表和其他附件；
- 识别常见 BDMV 结构，避免技术目录污染作品层级；
- 可报告进度、取消和错误；
- 在完成后清理本次范围内已经不存在的旧索引；
- 保留人工类型、显示名称、绑定、标签和收藏夹。

完整扫描可以为未绑定且合格的 Node 触发自动匹配。显式“匹配现有资源”只处理当前索引，不重新遍历磁盘。

### 3.3 分类

底层分类仍以视频分布为依据：

- `WORK` / `AUTO_WORK`：当前目录直接承载作品视频；
- `CONTAINER`：主要聚合下级作品，界面称“系列”；
- `MIXED`：同时包含直接视频和下级媒体分支，界面归入“其他资源”；
- `IGNORED`：用户明确忽略。

自动判断使用直接视频数、子媒体分支和总视频数。人工可设为作品、系列、其他资源、忽略或恢复自动判断；重新扫描不得覆盖人工选择。

SP、OVA、Extras 等补充目录不会仅因存在而把父目录错误拆散。非视频附件本身不能让目录成为作品或 Bangumi 候选。

## 4. 浏览、搜索与详情

### 4.1 浏览入口

侧栏包含：

- 全部资源：合并所有资源库中的可展示 Node；
- 搜索：跨索引搜索；
- 最近观看：按最近成功播放时间倒序；
- 收藏夹：一层命名集合；
- 每个 Library Root：按真实目录层级浏览；
- 设置。

全部资源和各集合支持海报网格或紧凑列表、标题/加入时间排序、筛选及编辑模式。

### 4.2 搜索

本地搜索可匹配：

- 数据库显示名称和真实文件夹名称；
- Bangumi 主标题及中、英、日、韩标题；
- 用户标签；
- 已索引视频文件名。

结果使用当前封面和本地化显示标题。搜索失败不得触发媒体目录写入。

### 4.3 详情页

打开新详情时滚动到顶部。详情展示封面、标题、Bangumi 信息、视频列表和附件列表。

- 视频按自然顺序排列，双击调用外部播放器；
- 附件按资源类型展示，可由 Windows 默认关联程序打开；
- 文件定位必须在资源管理器中选中准确文件；
- 打开系列时继续浏览其子节点；
- 返回列表时，在已有快照的情况下恢复浏览位置和控件状态。

## 5. Bangumi 与标题

### 5.1 网络边界

Bangumi 功能可在设置中关闭。启用时仅访问批准的 Bangumi 官方主机，使用 TLS 校验、系统代理、明确超时和有界请求；本地浏览不依赖该网络。

### 5.2 关键词提取

匹配证据可来自：

- 当前目录名；
- 代表性或高频视频文件名；
- 有帮助的父目录标题；
- 季度、年份和作品类型线索。

提取器应去除字幕组、编码、分辨率、校验码和集数等噪声，同时保留原始标题、拉丁转写、季度与续作信息。`S2`、`Season 2`、日文或中文季信息必须作为结构化证据，而不是随意并入作品主名。

### 5.3 自动匹配

普通自动匹配必须同时满足：

- Node 尚未绑定且允许自动匹配；
- 最多使用三个官方搜索关键词；
- 多个查询的候选按提供方排名公平合并；
- 只接受 Anime Subject；
- 多语言标题相似度、季、年份和类型没有强冲突；
- 最高候选达到高置信度阈值，并与次高候选保持足够领先。

中低置信度结果不能写入 `metadata_bindings`。普通自动流程不得替换已有绑定或手工封面。父目录含直接视频时，非人工分类的 SP、OVA、Extras 等补充子目录不参与自动匹配，但仍可手动绑定。

只有用户在编辑模式中明确执行“重新匹配所选”时，才允许在同一高置信度门槛下替换已有 Bangumi 绑定；手工封面仍不得被覆盖。

### 5.4 手动纠正与失败

用户可以手动搜索、选择、清除或重试绑定。封面下载失败时：

- 有效绑定必须保留；
- 记录并展示可理解的失败状态；
- 允许显式重试；
- 不回退为错误的其他条目。

### 5.5 多语言标题

支持 `zh-CN`、`en-US`、`ja-JP`、`ko-KR`。绑定标题选择顺序为：

1. 当前语言标题；
2. 中文标题；
3. Bangumi 主标题；
4. 数据库 `display_name`；
5. 真实 `folder_name`。

标题本地化只影响显示层，不改变路径。系列后缀也是本地化展示，不写入源目录。

## 6. 封面缓存

封面来源包括 Bangumi 下载、本地手工选择和占位图。下载或选择的文件只能写入应用拥有的缓存。

手工封面在写入前必须限制大小，校验 JPG、PNG、WEBP 的真实格式和合理像素尺寸，并通过缓存目录内临时文件原子提交。

用户可以修改活动封面缓存目录。新目录必须：

- 不位于任何 Library Root 内；
- 经过路径有效性检查；
- 在重启后保持；
- 不改变数据库中已有 Bangumi 绑定。

切换目录后不自动迁移或删除旧缓存，旧封面仍可按数据库路径读取。清理缓存只能删除应用确认拥有的活动缓存文件，不能递归删除无关用户文件。

海报保持正常浏览器插值。竖版封面铺满卡片；明显横版或接近方形的素材在竖框内完整显示，避免强制裁切放大导致锯齿。

## 7. 本地整理功能

### 7.1 用户标签

标签是规范化名称与 Node 的多对多关系。支持新增、重命名、删除、单项或批量赋予，并可用于筛选和搜索。标签只存在于应用数据库，与“作品 / 系列 / 其他资源”系统标签在视觉上保持区分。

批量操作必须先验证完整 Node 集，再使用事务提交；失败时不得留下部分修改。

### 7.2 收藏夹

收藏夹是侧栏下的一层命名集合：

- 一个 Node 可加入多个收藏夹；
- 支持创建、重命名、删除和批量加入/移出；
- 跨资源库使用；
- 删除收藏夹只删除集合及成员关系；
- 重新扫描保留成员关系，Node 正常删除时由外键清理。

### 7.3 最近观看

仅在外部播放器进程成功启动后记录对应 Node。每个 Node 保存最近时间和计数；列表按最近时间倒序。不得读取播放器历史、猜测观看状态或写入媒体文件。

## 8. 播放器与 Windows 集成

产品文案统一称“播放器”。兼容设置键 `mpv_path` 可以保留，mpv 只作为示例。

- 播放器路径由用户配置并可测试；
- 媒体路径作为原生进程的字面参数传递，不经过 shell 拼接；
- 普通附件使用 Windows 默认关联程序；
- “在资源管理器中显示”应选择准确文件；
- 应支持 Unicode、空格和特殊字符路径。

## 9. 设置、语言与主题

设置页修改自动保存，重启后恢复。主要设置包括：

- 外部播放器路径；
- 默认网格或列表模式；
- 视频扩展名；
- 是否启用 Bangumi；
- 界面语言；
- 主题；
- 活动封面缓存目录。

用户可见文案进入类型化 i18n 资源，支持简体中文、English、日本語、한국어。界面使用 Windows/system 字体栈，不捆绑字体文件。

主题使用语义 CSS 变量，提供 `system`、`light` 和 `dark`。跟随系统模式应在应用打开期间响应系统变化；暗色模式不是简单反色。

## 10. 导航与窗口状态

打开新详情时滚动位置为零。应用返回、`Alt+Left` 或 WebView 历史在有快照时恢复先前的滚动、筛选、排序、网格/列表和浏览层级。

侧栏目的地分别保留会话内快照：全部资源、搜索、最近观看、收藏夹及每个资源库。资源库和收藏夹恢复时必须重新装载当前数据库行，不能用旧快照覆盖扫描或元数据修改后的新数据。

全部资源、资源库浏览和收藏夹分别把最后排序写入 SQLite `settings`；它们与设置页整组 `AppSettings` 分离。主窗口关闭时保存一次有效尺寸，启动时在当前显示器范围内恢复。

## 11. 数据兼容与安全

- 所有 SQL 在 Rust 中执行；WebView 不直接访问数据库；
- 数据库改变使用增量 migration，不删除已有用户数据；
- 删除与批量写操作使用外键和事务维持一致性；
- 网络、文件选择和进程权限保持最小范围；
- 不提交密钥、令牌、个人文件路径、真实媒体索引、聊天记录或一次性需求全文；
- 公开构建必须检查产物中不存在构建者路径；
- Logo 使用仓库指定母版并按完整画布等比生成各尺寸，不重新设计或修改母版。

## 12. 当前非目标

当前版本不负责：

- 内置播放、在线视频或转码；
- 媒体服务器和远程串流；
- 账号、云同步和多人共享；
- 自动字幕、播放进度或续播；
- 自动移动、重命名或整理源文件；
- Bangumi 账号收藏、评分或观看状态同步。

## 13. MVP 验收标准

一个发布候选至少满足：

1. 可添加、扫描和移除多个 Library Root，媒体目录内容不发生变化；
2. Work / Container / Mixed 分类与人工覆盖在重扫后保持；
3. 全部资源、目录、搜索、最近观看和收藏夹可正常浏览；
4. 视频、非视频附件、打开和精确定位功能可用；
5. Bangumi 自动匹配只写入高置信度结果，手动纠错和封面重试可用；
6. 四种语言及三种主题均可切换并持久化；
7. 标签、收藏夹、最近观看、窗口尺寸和排序均按规格保存；
8. 老数据库通过增量 migration 升级且不丢失应用元数据；
9. TypeScript、前端构建、项目验证、Rust 格式、测试和 Clippy 全部通过；
10. Windows Portable 由正式脚本生成，通过版本、图标、隐私、校验和与启动检查。
